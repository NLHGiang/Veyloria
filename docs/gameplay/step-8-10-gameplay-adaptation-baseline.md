# 8.10 — Gameplay Adaptation Baseline

## Purpose

8.10 consolidates the decisions established throughout Step 8 into one stable gameplay baseline.

> **Step 8 defines how Veyloria should be played.**

Step 9 will define how the story becomes quests, mechanics, levels, maps and progression.

## Gameplay Identity

Veyloria is fundamentally a game about:

> **acting inside a world that remembers.**

Core sequence:

> **Explore → Notice → Investigate → Interact → Choose → Act → Consequence → Remember → Reinterpret**

## Player Fantasy

### Primary Fantasy
> **The Forgotten One**

The player is someone whose relationship with the world is larger than their own memory of it.

> **“I don't fully remember who I was, but the world does.”**

### Agency Fantasy
> **Today's actions become tomorrow's memories.**

## Five Gameplay Pillars

1. **Explore**
2. **Notice & Investigate**
3. **Interact & Change**
4. **Memory & Contradiction**
5. **Consequence & World Remembers**

## Core Gameplay Loop

> **Problem → Explore → Notice → Investigate → Act → World Changes → Consequence → New Question**

## Long-Term Loop

> **Player Action → World Remembers → Memory Conflict → Curiosity → Revisit → New Evidence → Reinterpretation**

## Session Baseline

Target meaningful session:

> **10–15 minutes**

A typical beat contains:
1. Situation
2. Problem
3. Player Action
4. World Response
5. State Change
6. Unresolved Question

## Interaction Model

> **Observe → Investigate → Interact → Choose → Act → Revisit**

Mechanical actions should carry narrative meaning whenever possible.

## World State Model

### Object
Can remember moved, repaired, broken, discovered, used, altered.

### Location
Can remember opened, damaged, restored, abandoned, changed, revisited.

### NPC
Can remember player actions, promises, help, betrayal, information, relationships.

### Systemic World
Can remember major decisions, act-level consequences, relationships, access, canonical events.

## Four Memory Layers

1. **Canonical Truth** — what actually happened.
2. **Character Memory** — what an NPC believes happened.
3. **Player Memory** — what the player believes happened.
4. **Player Interpretation** — what the player currently infers.

> **Memory ≠ Truth.**

The underlying world model must remain coherent even when memories disagree.

## Progression Baseline

Primary progression:

> **Understanding > Power**

Progression should increasingly come through knowledge, recognition, investigation, relationships, access, interpretation, evidence and understanding.

> **The player becomes better at reading Veyloria.**

## Unlock Philosophy

> **Understanding → Recognition → New Interaction → New Possibility**

Knowledge can function as progression.

## Quest Baseline

> **Question → Situation → Player Action → World Response → Consequence → New Question**

Quest objectives may be clear while narrative meaning remains uncertain.

## Story-to-Gameplay Baseline

> **Story Intent → Player Situation → Player Action → World Response → Player Discovery → Story Meaning**

Important story information should become playable whenever possible.

## Story Delivery

> **Infer > Discover > Show > Tell**

## Reveal Design

> **Old Memory → New Evidence → Contradiction → Reinterpretation → Realization**

Major reveals should recontextualize previous information rather than merely deliver exposition.

## Consequence Baseline

### Minor
Dialogue variation, object state, small NPC reaction.

### Significant
Relationship, quest, location, new/lost opportunity.

### Major
Act progression, persistent world state, major relationship shift, large-scale recontextualization.

> **Not every action needs a branch. Every meaningful action needs a trace.**

## Revisit Baseline

> **Old space → New evidence → New state → New meaning**

Revisit exists to create recontextualization, not merely content reuse.

## Failure Baseline

Failure may create memory, relationship change, missed opportunity, contradiction, future evidence or alternate interpretation.

> **Failure can be narrative information.**

## UI Baseline

UI should primarily represent:

> **What the player knows**

not:

> **What the world knows**

Journal may distinguish evidence, observation, interpretation, unresolved questions and contradictions.

## Pet Baseline

The pet is a natural hint system.

> **Suggest attention, do not solve investigation.**

## Content Cadence

Balance:
- discovery;
- action;
- consequence;
- quiet moments;
- relationships;
- ordinary life;
- unresolved questions;
- major revelations.

> **Mystery needs normality to create contrast.**

## Supporting Gameplay

Farming, fishing, cooking, decorating, collecting, light survival and combat may exist as supporting systems.

They must provide rhythm, atmosphere, world familiarity, breathing space or optional interaction.

They must not replace the core identity.

## System Introduction Gate

A new core mechanic must answer:

1. Which Player Fantasy does it serve?
2. Does it reinforce The World Remembers?
3. What does the player actually do?
4. What must the player notice?
5. Where is agency?
6. Can it create a narrative footprint?
7. Can it create contradiction or recontextualization?
8. Does it improve understanding rather than merely power?
9. Does it fit a meaningful 10–15 minute beat?
10. Does it add meaningful experience rather than generic complexity?

If it fails multiple tests, it should not enter core gameplay.

## Priority Rule

1. Player Fantasy
2. The World Remembers
3. Player Agency
4. Memory ≠ Truth
5. Meaningful Consequence
6. Understanding Progression
7. Session Clarity
8. Systemic Depth
9. Content Quantity

> **A small identity-strong system is better than a large generic system.**

## Gameplay Depth Model

Depth should primarily come from relationships between systems rather than number of systems.

> **Player action → NPC remembers → NPC changes → Player notices → Investigates → Contradictory evidence → Revisits → Reinterprets**

## Narrative Footprint Rule

Every major story event should have at least one gameplay footprint.

Every significant gameplay action should have the potential to create memory, state, relationship, evidence, consequence or future interpretation.

> **Story and gameplay must leave traces in each other.**

## Player Knowledge Model

The game must distinguish:

> **What happened**

from:

> **What the player thinks happened.**

The gap between these is a primary source of curiosity.

> **Player Fantasy → Gameplay Pillar → Core Loop → Player Action → World Response → Memory → Consequence → Understanding**

No future gameplay system should bypass this architecture without an explicit design reason.
